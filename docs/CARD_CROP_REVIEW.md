# 统一卡片裁剪工作台

打开本地页面：

```text
http://127.0.0.1:4321/tools/card-crop-review
```

端口以当前开发服务器输出为准。这个路由是内部编辑器，不加入站点导航，也不会进入 sitemap。

## 这版解决什么问题

这次改造把 **`/sayings` 和 `/traces` 归档页上的真实 `MediaCard`** 定义为唯一的裁剪基准。编辑器的 Step 2 不再绘制一张“看起来相似”的模拟卡，而是直接渲染同一个 `MediaCard` 组件；它内部继续使用同一个 `CardMediaFrame`。

因此以下规则只有一份来源：

- 卡片外层高度、宽度、左右布局、内外间距；
- 斜边的 polygon、左/右方向和移动端形状；
- `object-fit`、`object-position`、缩放和 transform-origin；
- hover 以外的正式卡片图片状态。

编辑器的 Step 1 会读取 Step 2 中真实媒体框的当前尺寸比例，再用同一套图片框让用户拖动、缩放。这样在同一浏览器宽度、同一非 hover 状态下，编辑器预览与归档卡片看到的是同一块源图区域，而不是只“共用几条 CSS”。

每个源文件仍只在队列中出现一次；Saying 和 Trace 复用同一文件时共享一份记录。Hero 不进入这个队列：它是全幅背景，没有斜边，使用独立的 `HeroMediaFrame` 和桌面/手机定位记录。

## 已确定的场景边界

| 场景                           | 本次决定                           | 说明                                                                                                                            |
| ------------------------------ | ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| `/sayings`、`/traces` 归档卡片 | **主基准，必须一致**               | 编辑器预览直接使用正式组件；桌面和手机都按真实卡片尺寸验证。                                                                    |
| Home 的 Recent/随机 Saying     | **辅助检查，不承诺像素级完全一致** | Home 有紧凑卡片高度、54% 图片列和不同的底部信息条；默认沿用归档配置，必要时以后再加场景覆盖。                                   |
| 手机端焦点                     | **本次先沿用同一份焦点/缩放**      | 手机端会改变卡片排版和媒体框比例，编辑器会显示该真实比例；若后续某张图必须单独调整，可增加 mobile override。                    |
| 不同场景是否允许不同配置       | **允许，但只作为显式例外**         | 默认记录服务归档卡片；Home/mobile 覆盖必须明确写入配置，不能隐式按页面或索引改变。                                              |
| `cropRects`                    | **继续保留**                       | 它是导出/审计用的源图相对矩形，按参考框推导；运行时真正决定画面的仍是 `fit + transform + frame`，不会把矩形偷偷当成另一套裁剪。 |

不同宽高比不可能由一个固定的像素矩形在所有页面都保持完全相同；本次解决的是主场景的真实组件复用和同视口一致性，而不是把 Home 的另一种布局伪装成归档卡片。导出 JSON 中的 `frame`（640×448）只是稳定的参考/审计坐标；运行时不会按这个旧比例重新裁一遍图片。

## 归档排列与开发占位内容

桌面卡片只有两种合法布局：`图片在左 + 斜边在右`、`图片在右 + 斜边在左`。归档构建时会按每张素材已经确认的 frame 拆成两个固定队列，并从“图片在左”开始严格左右交替。素材不会因为列表位置而被翻转；当两个队列长度不同时，较短队列会均匀重复少量图片，以换取整页严格交替。

完整审阅批次在生成开发占位内容后会生成 38 个 Saying 槽位（34 张唯一图片、4 次重复）和 24 个 Trace 槽位（20 张唯一图片、4 次重复）。当前 release-prep 候选不包含这些占位文章，Trace 集合为空；需要临时检查完整卡片队列时，运行以下命令会只补足缺少的数量，不会覆盖现有内容：

```text
bun run card-preview:generate
```

占位文章是正常通过内容层渲染的真实详情与归档卡片，因此临时查看 `/sayings` 和 `/traces` 得到的是最终组件效果，不是另一套模拟预览。当前素材队列会补齐到 Saying 38 个、Trace 24 个槽位（队列变化时以脚本输出为准）；审阅完成后，必须按 `card-preview-*` 前缀移出仓库。它们不属于当前发布内容，即使 `.gitignore` 已覆盖该命名也不能留在工作树中，因为会改变构建页数、RSS、Pagefind 和回归结果。

## 页面操作

1. 左侧队列选择素材；搜索框、用途筛选和状态筛选可以缩小范围。
2. 在“斜边在左/斜边在右”之间切换。两个正式框各自保留独立的焦点和缩放值；画布比例会自动跟随下方真实卡片媒体框。
3. 在画布上按住鼠标或触控拖动图片；滚轮、`+/-`、滑杆控制缩放。方向键每次移动 2%，按住 Shift 为 5%。
4. “完整显示”适用于不应该被裁掉的素材；它不会改变源文件，只改变预览和导出记录的适配方式。
5. 点击“确认当前框”确认一个方向；如果两个方向都满意，点击“两个框都可以”；两个方向都无法接受时点击“两个框都不合适”，它会留在待处理/异常筛选中，不会偷偷套用一个结果。
6. “确认并处理下一张”会跳到下一张尚未确认的素材。撤销/重做最多保留 60 个操作，草稿会自动保存到当前浏览器。
7. 每次确认都会在当前素材、当前斜边下写入一份不可变的“确认版本”（最多 20 份）。确认之后如果误拖动或误缩放，裁剪状态会自动变回“待处理”，此时点击“恢复最近确认”即可回到最近一次已确认构图；这次恢复也会进入普通撤销记录。
8. 点击“查看确认历史”可以看到当前斜边的所有版本。对旧版本可选择“载入草稿”（载入后先检查，再点正常确认）或“恢复并确认”（会弹出二次确认）。因此先确认 A、再确认 B 后，A 仍可随时找回；普通“撤销/重做”不会删除这些确认历史。
9. 如果要重新审阅整批素材，点击工具栏的“取消全部确认”。二次确认后，所有 `diagonal-left`、`diagonal-right`、`both` 会改回“待处理”；焦点、缩放、`contain/cover`、两个方向的草稿和确认历史都保留。它只改浏览器草稿，不会直接改正式页面，也不会删除生产桥接文件。
10. 使用“导出裁剪配置”下载 JSON。确认历史会一并导出（`confirmationHistoryVersion: 1`）；换电脑或清空浏览器后，可用“导入配置”恢复。旧版没有历史字段的配置会自动用当前已确认值建立一个可恢复的初始版本。

浏览器下载的 `card-crop-editor-v2.json` 与 `hero-crop-editor-v1.json` 是审阅输入，不是发布源；请保存到仓库外或已忽略的 `artifacts/` 目录，不要保存到仓库根目录。若误下载到根目录，完成导入/应用后必须移出，再检查 `git status`。

键盘快捷键：画布聚焦时，方向键移动焦点，`+`/`-` 缩放，`R` 重置当前位置，`Enter` 确认当前框并跳到下一张。

## Hero 的单独处理

在页面顶部切换到“Hero 定位”标签。六张 Hero 共用一个全幅预览框：

1. 选择 Hero 幻灯片，并在真实的 Home Hero 舞台中拖动图片、滚轮或滑杆缩放。编辑器直接复用 `HeroGallery` 和 `HeroMediaFrame`，不是另画一张近似图；内部先按 Home 的实际像素尺寸建立舞台，再整体等比缩小到工作台，因此图片、Logo、遮罩、波浪和安全区使用同一套坐标。桌面/手机舞台高度跟随 Home 的 `clamp(70vh/62vh)` 规则。
2. 分别切换“桌面”和“手机”预览；两个尺寸保存各自的焦点和缩放，不能假定同一个位置在两种比例下都合适。
3. “静态构图”用于精确检查源图焦点；“运行预览（暂停/播放）”用于查看 Hero 的缩放动效。运行预览只挂载当前选中的一张图，因此不会模拟六张图之间的轮播淡入淡出，也不会影响导出的裁剪值。
4. 点击“确认当前尺寸”。“复制到另一尺寸”只复制草稿，仍需要在另一尺寸检查并确认。
5. 每次确认都会按当前尺寸写入独立的确认版本，桌面和手机互不覆盖。误操作后点击“恢复最近确认”；如需找回更早版本，打开“查看确认历史”，可载入草稿或“恢复并确认”。普通“撤销/重做”不会抹掉确认历史。
6. 如需从头检查已应用结果，点击“加载已应用配置”；如需整批重新确认，点击“取消全部确认”。后者只清除桌面/手机确认标记，不会丢失焦点、缩放或历史版本。
7. 导出 `hero-crop-editor-v1.json`，检查后用 `hero-crops:apply` 写入生产桥接文件。确认历史会随编辑器 JSON 保存，但应用脚本只读取当前明确确认的桌面/手机 transform，不会把历史版本写进生产桥接。未应用前，正式 Hero 保持居中 cover 回退。

```text
bun scripts/apply-hero-crops.mjs path/to/hero-crop-editor-v1.json --dry-run
bun scripts/apply-hero-crops.mjs path/to/hero-crop-editor-v1.json
```

脚本只写入 `src/data/hero-crop-selections.generated.ts`，不会改写原图，也不会改变 Saying/Trace 卡片。新格式会严格只应用明确确认的桌面/手机尺寸；未确认尺寸会保留已有生产值。没有 `confirmed` 字段的旧版导出按历史兼容规则视为已确认。

## 将确认结果接入正式卡片

浏览器导出的文件不会自动修改仓库，这是为了避免一次误操作直接改变线上页面。确认并检查 JSON 后，在项目根目录执行：

```text
bun scripts/apply-card-crops.mjs path/to/card-crop-editor-v2.json --dry-run
bun scripts/apply-card-crops.mjs path/to/card-crop-editor-v2.json
```

也可以使用等价的 npm script：

```text
bun run card-crops:apply -- path/to/card-crop-editor-v2.json
```

脚本只会写入 `src/data/card-crop-selections.generated.ts`。它会检查文件名是否属于 `public/images/home-media`、读取源图尺寸，并为两个框计算 0–1 的标准化 crop rectangle。未确认、标记为“两个框都不合适”或找不到源文件的条目会被跳过并列出原因。
带有 `profile` 字段的输入必须是 `archive-card`；这样误把 Hero 配置交给卡片脚本时会直接停止，不会写入生产桥接文件。旧版没有 `profile` 的卡片导出仍可兼容导入。

`MediaCard` 通过 `ResolvedCardImage.crop` 读取已应用记录；没有应用记录时继续使用现有的 asset-specific 斜边和居中 cover 回退。因此编辑器可以先完整审阅 54 张图，再一次性接入生产。

## 数据与安全边界

- 浏览器草稿键：`susurrium:card-crop-editor:v2`。
- 确认历史只存在编辑器草稿中，按素材与斜边（Hero 则按素材与桌面/手机）分开保存，最多 20 个版本；工具栏的“清空草稿”会连同本地历史一起清除，若只是想重新审核请使用“取消全部确认”。
- 生产记录 schema：`2`，定义在 `src/lib/card-crop/types.ts`。
- 当前导出 profile：`archive-card`，机器可读范围在 `cardCropPolicy`：Saying/Trace 是主基准，Home 是辅助检查；手机先沿用同一焦点/缩放，场景覆盖只能显式记录。
- 原始 WebP 永远保留，不会被覆盖；导出和应用只写裁剪元数据。
- “两个框都可以”可以带一个 preferred frame；生产层若没有明确可用的单一结果，会使用安全的旧回退，不会让图片消失。
- 极端超宽图、需要同时保留多个不相邻主体的图，仍可能需要选择 `contain` 或标记为不合适；统一工作流不等于所有构图都能自动完美。
